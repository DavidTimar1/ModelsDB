    Writing a search
    
      
    These boxes all read the same search: the main search, a column's text box, the search above a column's list of values, the search in the Columns dialog, and the search for the model to file a variation under. Half-typed text is never refused. It is read as far as it goes.
    
      
    The rules
    
      
      
        
    • Plain words: every word must appear, in any order. gpt 4o finds a name holding both gpt and 4o.
      • 
        
    • A phrase in double quotes must appear exactly as written, spaces included. "gpt 4o" finds only names with gpt 4o in a row.
      • 
        
    • A ! at the start of a word or a phrase leaves it out. gpt !mini finds gpt without mini. !"gpt 4o" leaves out that phrase.
      • 
        
    • OR means either side. claude OR gemini finds both families.
      • 
        
    • AND means the same as a space. vision AND audio is the same as vision audio.
      • 
        
    • AND is applied before OR. a b OR c means a and b, or c.
      • 
        
    • Only capital AND and OR are operators. and and or in small letters are ordinary words.
      • 
        
    • There are no parentheses. (free) is plain text with brackets in it.
      • 
        
    • A ! inside a word is just a letter. gpt-4o! does not exclude anything.
      • 
        
    • Capitals in your words are ignored. GPT and gpt find the same models.
      • 
      
    
      
    Two rules you might not guess
    
      
      
        
    • In a column that holds a list, each word may be found in a different item of the list. A quoted phrase must sit inside one item.
      • 
        
    • A ! word also keeps the models that have no value in that column. In the notes column, !draft finds every model with no note, as well as the notes that do not say draft.
      • 
      
    
      
    For an assistant or a script
    
      
    The API reads the same search through name= and contains:. For example /api/models?name=claude%20!haiku lists the Claude models without haiku.

      Add a variation
      
    
      A variation is a file you fetch from HuggingFace and run on your own machine: the same model with each weight stored in fewer bits, so it takes less space. Recording one here keeps a note of where it is and how big it is. Nothing is downloaded.
      
    
      
    
    
      
      
    
      
    
      
    
      
    
      
      
    
      
    
      

    
    
      
      
      Or file a model you already have under this one
      
      
      If a version of this model is already a row of its own, file it here instead of recording it again. Nothing is downloaded and nothing is looked up: the row keeps its note, its favourite star, every column value and every figure it holds, and gains one fact - that it is a variation of this model. It becomes hidden, like every variation, which does not take it off the screen: it moves out of the model list and appears under this model instead. If you have set the Hidden dropdown to "Hide all hidden", set it back to "Show all hidden" - or set the Variations filter to "Has variations" - to see it there.
